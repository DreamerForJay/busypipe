BusyPipe

嵌入式資料管線工具鏈

lparser lfilter lstore

以 POSIX C11 打造的輕量 ETL 工具組，為資源受限的 BusyBox / Linux 環境設計。 三個小工具透過 UNIX pipe 串接，在無額外依賴的條件下完成日誌解析、過濾與持久化儲存。

成果簡介

BusyPipe 是什麼，以及我們解決了哪些問題。

在嵌入式 Linux / BusyBox 環境中，往往缺乏 awk grep Python 等重量級工具，卻需要即時分析伺服器日誌、過濾異常事件並持久化儲存。

BusyPipe 以三個輕量 C 工具回應這個需求：透過標準 UNIX pipe 組合， 不需要任何外部依賴，便可在數 MB 記憶體的設備上完成完整 ETL 流程。

所有工具符合 POSIX C11 標準，並附有完整的 BusyBox applet 適配， 可直接編譯進 BusyBox multi-call binary，部署至嵌入式設備。

POSIX C11 BusyBox 1.36 UNIX pipe regcomp / regexec CSV · JSONL TTL KV Store
busypipe — pipeline demo 
# HTTP 錯誤分析管線
$ lparser --format nginx --csv \
    < samples/nginx.log \
  | lfilter --where 'status>=400' \
           --select 'ip,path,status' \
  | lstore  --db data/errors.tsv \
           --put --key-field ip --ttl 3600

# 查詢 KV Store
$ lstore --db data/errors.tsv --list
ip              path        status
192.168.1.3     /admin      403
10.0.0.2        /login      401
172.16.0.8      /api/secret 500

# SSH 失敗偵測
$ lparser --format auth --csv \
    < samples/auth.log \
  | lfilter --contains 'result=Failed' \
  | lstore --db data/ssh_fail.tsv \
           --put --key-field src_ip --ttl 86400

專案亮點

六個讓 BusyPipe 與眾不同的設計決策。

⚙️
POSIX C11 零依賴

只使用標準 C library 與 POSIX 介面，不依賴任何第三方套件。 可在任何符合標準的 UNIX 環境直接編譯，跨平台、跨發行版。

🔗
UNIX pipe 原生組合

每個工具嚴守「做好一件事」原則，透過 stdin / stdout 無縫串接。 可任意組合，也可與 shell 現有工具混搭使用。

📦
BusyBox 整合就緒

提供完整 BusyBox applet 適配版（*_bb.c） 與共用函式庫 libpipe，可直接編譯進 BusyBox multi-call binary。

🔍
多格式日誌解析

內建 nginx、Apache、auth.log 三種預設格式，並支援 --regex + --fields 自訂模式，輸出 CSV 或 JSONL。

💾
TTL 自動過期 KV Store

lstore 提供完整 CRUD 與 TTL 到期清理， 以 rename() atomic rewrite 確保資料一致性， 並支援 buffered write 提升吞吐量。

⚡
效能超越 GNU awk

在 50,000 行日誌的解析過濾場景中，BusyPipe pipeline 吞吐量 優於等效 GNU awk 指令，且記憶體用量顯著更低。

使用場景

從嵌入式設備到雲端伺服器，BusyPipe 涵蓋的實際應用情境。

🔒
SSH 暴力破解偵測

即時解析 auth.log，過濾失敗登入事件，依來源 IP 記錄並設 TTL，自動清除過期威脅。 

$ lparser --format auth --csv < /var/log/auth.log \
  | lfilter --contains 'result=Failed' \
  | lstore --db /tmp/threats.tsv \
           --put --key-field src_ip --ttl 86400
📡
IoT 嵌入式設備日誌

在記憶體僅 4 MB 的嵌入式裝置上，透過 BusyBox multi-call binary 執行完整管線，無需安裝額外工具。 

# BusyBox applet 版本
$ busybox lparser --format nginx --csv \
    < /var/log/access.log \
  | busybox lfilter --where 'status>=500' \
  | busybox lstore --db /tmp/errs.tsv --put
🗂️
自訂格式日誌解析

使用 --regex 與 --fields 定義任意日誌格式，輸出標準化 CSV 供後端直接處理。 

# 自訂應用程式日誌格式
$ lparser \
  --regex '(\d+) \[(\w+)\] (.+)' \
  --fields 'ts,level,msg' \
  --csv < app.log \
  | lfilter --where 'level==ERROR' \
           --select 'ts,msg'
🧹
定期清理 + 查詢統計

搭配 cron 定期執行 --cleanup 清除過期記錄，再用 --count 與 --stats 掌握目前狀態。 

# cron: 每小時清理 + 統計
$ lstore --db /tmp/threats.tsv --cleanup
Removed 12 expired records.
$ lstore --db /tmp/threats.tsv --count
4 records
$ lstore --db /tmp/threats.tsv --stats
total: 16  active: 4  expired: 12

架構設計

三個工具如何分工協作，組成完整的 ETL 管線。

1
lparser 原始日誌解析器
▸從 stdin 讀取原始日誌
▸POSIX regex 欄位擷取
▸輸出 CSV（含 header）或 JSONL
▸nginx / apache / auth 預設格式
▸--stats matched / skipped 統計
2
lfilter CSV 串流過濾器
▸數值比較 --where 'status>=400'
▸子字串過濾 --contains
▸欄位投影 --select
▸支援 6 種比較運算子
▸CSV / JSONL 雙輸出格式
3
lstore 持久化 KV Store
▸完整 CRUD：put / get / delete / list
▸TTL 自動過期與 cleanup
▸atomic rewrite（rename()）
▸buffered write（64行 / 128KiB）
▸--stats 操作統計
Pipeline 1 — HTTP 錯誤分析 
# 解析 → 過濾 4xx/5xx → 寫入 KV store
$ lparser --format nginx --csv \
    < samples/nginx.log \
  | lfilter --where 'status>=400' \
           --select 'ip,path,status' \
  | lstore --db data/errors.tsv \
           --put --key-field ip --ttl 3600

$ lstore --db data/errors.tsv --get 192.168.1.3
192.168.1.3  /admin  403  1719500000
Pipeline 2 — SSH 失敗登入偵測 
# auth.log → 只保留失敗 → 記錄來源 IP
$ lparser --format auth --csv \
    < samples/auth.log \
  | lfilter --contains 'result=Failed' \
  | lstore --db data/ssh_fail.tsv \
           --put --key-field src_ip --ttl 86400

$ lstore --db data/ssh_fail.tsv --list
10.0.0.8   Failed  root  1719500000

指令參考

三個工具的完整選項一覽，搭配 --help 隨時查閱。

lparser 原始日誌解析器
--format nginx|apache|auth

內建快速路徑解析，繞過 regexec() 提升速度

--regex <pattern>

自訂 POSIX ERE 正規表示式

--fields <f1,f2,...>

對應 regex capture group 的欄位名稱

--csv

輸出 CSV（預設，含 header 行）

--jsonl

輸出 JSONL（每行一個 JSON 物件）

--stats

結束時輸出 matched / skipped 計數

lfilter CSV 串流過濾器
--where '<field><op><val>'

比較運算子：== != > >= < <=，自動判斷數值 / 字串型別

--contains <string>

子字串過濾，補 --where 無法處理的模糊匹配

--select <f1,f2,...>

欄位投影，只輸出指定欄位（保留順序）

--format csv|json

輸出格式（預設 csv；json 輸出 JSONL）

欄位不存在時輸出可用欄位清單，方便除錯

lstore 持久化 KV Store
--db <file>

TSV 資料庫檔案路徑（必填）

--put --key-field <f> --ttl <sec>

從 stdin 讀 CSV 寫入；0 = 永不過期

--get <key>

查詢最新有效記錄

--delete <key>

刪除指定 key（atomic rewrite）

--list --count --cleanup

列出 / 計數 / 清除過期記錄

--stats

顯示 total / active / expired 統計

快速上手

從取得原始碼到跑完完整管線，四步搞定。

01
取得原始碼

Clone GitHub 儲存庫或下載 Release 壓縮檔到本機或嵌入式設備。

02
編譯

任何 POSIX Linux 環境執行 make， 零外部依賴，幾秒內完成。

03
驗證

執行 make test 跑 9 個 smoke test，確認三工具均正常。

04
使用

透過 UNIX pipe 串接三個工具，即可建立完整的日誌分析管線。

bash — build & run 
# 1. 取得原始碼
$ git clone https://github.com/DreamerForJay/busypipe.git && cd busypipe

# 2. 編譯（需要 gcc 與 POSIX make）
$ make
CC  src/lparser.c  →  build/lparser
CC  src/lfilter.c  →  build/lfilter
CC  src/lstore.c   →  build/lstore
✓  Build complete.

# 3. 執行 smoke test（9 個場景）
$ make test

9/9 tests passed.

# 4. 執行完整管線

  | lfilter --where 'status>=400' \

3 records

效能對比

BusyPipe vs GNU awk — 50,000 行 nginx 日誌的代表性基準測試， 以 scripts/benchmark.sh --lines 50000 --repeat 5 取平均值。

⚡ 解析吞吐量（行 / 秒）
BusyPipe lparser 52,400
GNU awk 37,800
⚡ 過濾吞吐量（行 / 秒）
BusyPipe lfilter 89,200
GNU awk（條件過濾） 71,500
💾 記憶體峰值（MB） 越低越好
BusyPipe pipeline 2.4 MB
GNU awk equivalent 8.1 MB
⏱️ 端對端管線時間（ms，50k 行）
BusyPipe 三工具串接 ~950 ms
GNU awk 腳本 ~1,320 ms

測試環境：Linux 6.6 · x86_64 · 單核 · samples/ 樣本放大至 50,000 行。 數值為代表性結果，實際效能因硬體與系統負載而異。

BusyBox 整合

將 BusyPipe 三工具編譯進 BusyBox multi-call binary，部署至嵌入式 Linux 設備。

提供的整合檔案
busybox/libpipe.h 共用函式庫介面宣告
busybox/libpipe.c 共用函式庫實作（→ libbb/busypipe_lib.c）
busybox/lparser_bb.c applet 適配版（入口 lparser_main）
busybox/lfilter_bb.c applet 適配版（入口 lfilter_main）
busybox/lstore_bb.c applet 適配版（入口 lstore_main）
驗證（不需 BusyBox 原始碼）
make test-bb 22 項整合驗證，含編譯 + 功能 + 輸出一致性
bash — BusyBox 1.36 整合步驟 
# 1. 複製 applet 適配版本
$ cp busypipe/busybox/lparser_bb.c  busybox-1.36/miscutils/lparser.c
$ cp busypipe/busybox/lfilter_bb.c  busybox-1.36/miscutils/lfilter.c
$ cp busypipe/busybox/lstore_bb.c   busybox-1.36/miscutils/lstore.c

# 2. 複製共用函式庫
$ cp busypipe/busybox/libpipe.c  busybox-1.36/libbb/busypipe_lib.c
$ cp busypipe/busybox/libpipe.h  busybox-1.36/include/libpipe.h
$ echo "lib-y += busypipe_lib.o" >> busybox-1.36/libbb/Kbuild

# 3. 啟用 applet 並編譯
$ make defconfig && echo "CONFIG_LPARSER=y
CONFIG_LFILTER=y
CONFIG_LSTORE=y" >> .config
make oldconfig && make -j$(nproc)

# 4. 確認三個 applet 存在
$ ./busybox --list | grep -E 'lparser|lfilter|lstore'
lfilter
lparser
lstore

# 5. 執行完整管線
$ ./busybox lparser --format nginx --csv < access.log \
  | ./busybox lfilter --where 'status>=400' \
  | ./busybox lstore --db errs.tsv --put --key-field ip
✓ 3 records written.
